# Видеоконтроль опасных зон и СИЗ на складе

Система смотрит видео с камер склада и сообщает о нарушениях техники безопасности:

- человек слишком долго стоит в опасной зоне (зона работы погрузчика, проход у стеллажей во время загрузки);
- человек работает без каски или сигнального жилета.

Сейчас такие нарушения ищут вручную по записям, и большинство из них никто не замечает. Здесь система находит нарушение сама и присылает оператору тревогу с коротким клипом, а оператор только подтверждает её или отмечает как ложную.

Подробно про задачу, метрики и план решения — в [дизайн-документе](docs/ml_system_design_doc.md).

## Как это работает

1. Из видеопотока берутся 2–5 кадров в секунду.
2. Детектор находит людей, каски и жилеты.
3. Трекер ByteTrack ведёт каждого человека между кадрами.
4. Правила по зонам, размеченным для каждой камеры, решают, есть ли нарушение.
5. При нарушении сохраняется клип и уходит тревога оператору.

Решения оператора потом используются как разметка для дообучения модели.

## Статус

Готовы дизайн-документ, pre-commit и [подробный EDA двух видео](reports/eda/README.md):
`Camera_0000.mp4` и `input.mp4`, всего 77,16 секунды и 2229 кадров.
В ДЗ2 описаны подготовка данных, моделей, правила и офлайн-проверка.
[Предразметка обоих роликов](reports/annotations/README.md) пересчитана на каждом
кадре; есть 2 зоны, 4 кандидата событий и визуальная сверка 20 кадров.
Следующий шаг — исправление аннотаций и правил на этих же видео.
Новых съёмок, дообучения и промышленного пилота в текущей итерации нет.

## ДЗ2: соответствие критериям

| Критерий задания | Вес | Где находится результат |
| --- | ---: | --- |
| Провести EDA: состав, объём, качество, визуализации и выводы | 4 | [Отчёт EDA](reports/eda/README.md), CSV и графики качества по времени; [оценка разметки](reports/annotations/README.md#визуальный-аудит) на 20 кадрах, размеры объектов и треки; [воспроизводимый код](scripts/eda.py) |
| Описать подготовку данных | 2 | [Этап 1](docs/ml_system_design_doc.md#этап-1-подготовка-данных): сущности, источник и регулярность поступления MP4, проблемы EDA, необходимый дополнительный объём, конфиденциальность и результат этапа |
| Описать подготовку прогнозных моделей | 2 | [Этап 2](docs/ml_system_design_doc.md#этап-2-подготовка-прогнозных-моделей): метрики и потери с обоснованием, групповая валидация, предобработка и бейзлайн, развитие MVP, подбор параметров, анализ ошибок, риски и результат |
| Описать этапы, специфические для задачи | 2 | [Этап 3](docs/ml_system_design_doc.md#этап-3-правила-зон-и-сиз): зоны, длительность, СИЗ и треки; [этап 4](docs/ml_system_design_doc.md#этап-4-инференс-и-проверка-на-складе): инференс, ресурсы и офлайн-проверка |

Выполненные эксперименты: анализ двух видео, предразметка всех 2229 кадров,
демонстрационные зоны и события, визуальная сверка количества объектов на 20 кадрах.
Улучшение правил, эталонные рамки и модельные метрики описаны как следующие этапы.
Ошибки предразметки и границы проведённой оценки указаны в отчётах.
Исходные MP4 и видео с наложением доступны локально; повторный расчёт требует исходников.

## Стек

Python 3.12, ONNX Runtime, ByteTrack, FastAPI, PostgreSQL, RabbitMQ, S3, Docker, GitHub Actions.

## Структура репозитория

```
.
├── docs/
│   └── ml_system_design_doc.md   # дизайн-документ
├── data/README.md                # источник и доступ к видео
├── data/annotations/             # предразметка всех кадров и события
├── data/demo_zones.json          # условные зоны
├── scripts/eda.py                # расчёт EDA
├── scripts/annotate.py           # полная автоматическая предразметка
├── scripts/annotation_quality.py # сравнение с визуальным аудитом
├── reports/eda/                  # отчёт, CSV и график
├── reports/annotations/          # оценка разметки; видео локально в previews/
├── requirements-eda.txt          # зависимости EDA
├── requirements-annotation.txt   # зависимости предразметки
├── .pre-commit-config.yaml       # хуки pre-commit
├── pyproject.toml                # настройки ruff
└── README.md
```

Исходные видео лежат локально в `video/` и не попадают в Git.
В расчётах выбраны только `Camera_0000.mp4` и `input.mp4`; другие файлы игнорируются.

## Повторить EDA (ДЗ2)

```bash
python -m pip install -r requirements-eda.txt
python scripts/eda.py --files Camera_0000.mp4 input.mp4
```

## Как начать работать с репозиторием

```bash
git clone https://github.com/NeoRassinin/cctv-danger-zone.git
cd cctv-danger-zone

python -m venv .venv
source .venv/bin/activate

pip install pre-commit ruff
pre-commit install               # хуки будут запускаться на каждом коммите
```

Проверить весь код вручную:

```bash
pre-commit run --all-files       # все проверки разом
ruff check .                     # только линтер
ruff format .                    # только форматирование
```
